# 홈페이지 완료 자동문자 발송 기획서

**작성일**: 2025-11-14
**목적**: 관리자가 홈페이지 제작 완료 설정 시 고객에게 자동으로 안내 문자 발송

---

## 1. 트리거 조건

- **이벤트**: 관리자가 해당 신청 건의 "홈페이지 제작 완료" 상태로 변경
- **발송 대상**: 신청 고객의 연락처 (DB에 저장된 전화번호)
- **발송 타이밍**: 상태 변경 즉시 자동 발송

## 4. 기술 구현 방안

### 4-1. SMS 발송 API (현재 시스템 활용)

- **현재 사용 중인 SMS API 활용** (예: Solapi, NHN Cloud SMS, Aligo 등)
- **발송 로직**:
  1. 관리자가 "홈페이지 완료" 상태로 변경
  2. 백엔드에서 상태 변경 감지 (Webhook 또는 DB Trigger)
  3. SMS API 호출하여 문자 발송
  4. 발송 결과 로그 저장

### 4-2. 카카오 알림톡 (선택사항)

- **장점**: 무제한 발송 가능, 버튼 및 링크 추가 가능
- **단점**: 카카오 비즈니스 계정 필요, 템플릿 사전 승인 필요
- **비용**: 기본 무료 (일부 유료 옵션)

### 4-3. 구현 우선순위

1. **1단계**: 기본 SMS 발송 (버전 2 간략형 추천)
2. **2단계**: 관리자 페이지에서 발송 내역 확인 기능
3. **3단계**: 카카오 알림톡 연동 (선택)

## 5. DB 스키마 추가 (필요 시)

### 5-1. 기존 테이블 확장

**Application 테이블에 추가 필드**:
```typescript
model Application {
  // 기존 필드...

  homepageUrl       String?   // 홈페이지 주소
  homepageCompleted Boolean   @default(false)  // 홈페이지 완료 여부
  completedAt       DateTime? // 완료 시각
  smsNotified       Boolean   @default(false)  // 문자 발송 여부
  smsNotifiedAt     DateTime? // 문자 발송 시각
}
```

### 5-2. SMS 발송 로그 테이블 (선택)

```typescript
model SmsLog {
  id            String   @id @default(cuid())
  applicationId String   // 신청 ID
  phoneNumber   String   // 수신 번호
  message       String   @db.Text // 발송 내용
  status        String   // 발송 상태 (success, failed)
  errorMessage  String?  // 실패 시 에러 메시지
  createdAt     DateTime @default(now())

  application   Application @relation(fields: [applicationId], references: [id])
}
```

## 7. API 엔드포인트

**요청 본문**:
```json
{
  "homepageUrl": "https://example.imweb.me"
}
```

**응답**:
```json
{
  "success": true,
  "message": "홈페이지 완료 처리 및 문자 발송 완료",
```

## 9. 예상 비용

### SMS 단문 (90바이트 이하)
- **버전 2 (간략형)**: 약 200바이트 → **장문 SMS** (건당 약 20~30원)
- **버전 1 (기본형)**: 약 350바이트 → **장문 SMS** (건당 약 30~40원)

### 카카오 알림톡
- **기본**: 무료 (월 1,000건 이내)
- **유료**: 건당 약 7~10원 (대량 발송 시)

**💡 권장**: 초기에는 **버전 2 (간략형 SMS)** 사용 후 고객 반응 확인
