## 개요

### 목적
- 광고자동화 **시점 관리** (광고자동화 기능 자체는 별도 진행)
- 관리자가 사용자별 광고자동화 On/Off 상태 및 시점 기록
- 제작물 완료 현황과 광고자동화 상태를 한눈에 확인
- 마케팅 지원 종료일과 연동하여 직관적으로 표시
- 유료 전환 시점 관리

### 핵심 기능
1. **광고자동화 토글** - 관리자가 켜짐/꺼짐 상태만 기록 (실제 기능은 별도)
2. **시점 이력 관리** - 켜진/꺼진 시점 상세 기록
3. **제작물 현황 대시보드** - 완료/미완료 상태 시각화 (🟢/🔴)
4. **마케팅 지원 기간 표시** - 종료일과 남은 기간 직관적 표시
5. **유료 결제 시점 관리** - 결제일 및 서비스 기간 기록

## 데이터베이스 설계

### 1. User 테이블 확장 (기존 스키마 수정)

```prisma
model User {
  // ... 기존 필드

  // 🆕 광고자동화 상태
  adAutomationEnabled   Boolean   @default(false) // 광고자동화 활성화 여부
  adAutomationStartDate DateTime? // 광고자동화 시작일
  adAutomationEndDate   DateTime? // 광고자동화 종료일 (마케팅 지원 종료일과 동일)

  // 관계
  adAutomationHistory   AdAutomationHistory[]
  adAutomationPayments  AdAutomationPayment[]
}
```

### 2. 광고자동화 이력 테이블 (신규)

```prisma
model AdAutomationHistory {
  id     String @id @default(cuid())
  userId String
  user   User   @relation(fields: [userId], references: [id], onDelete: Cascade)

  // 이력 정보
  action      String   // "enabled" | "disabled"
  actionBy    String   // 관리자 ID
  actionByName String  // 관리자 이름
  reason      String?  @db.Text // 사유 (선택)

  // 기간 정보
  startDate DateTime? // 활성화 시작일
  endDate   DateTime? // 활성화 종료일

  createdAt DateTime @default(now())

  @@index([userId])
  @@index([createdAt])
  @@map("ad_automation_history")
}
```

### 3. 광고자동화 결제 테이블 (신규)

```prisma
model AdAutomationPayment {
  id     String @id @default(cuid())
  userId String
  user   User   @relation(fields: [userId], references: [id], onDelete: Cascade)

  // 결제 정보
  paymentDate    DateTime // 결제일
  paymentAmount  Int      // 결제 금액 (원)
  paymentMethod  String   // "카드" | "계좌이체" | "현금"
  receiptUrl     String?  // 영수증 URL

  // 기간 정보
  serviceStartDate DateTime // 서비스 시작일
  serviceEndDate   DateTime // 서비스 종료일 (결제일 + 1개월)

  // 상태
  status         String   @default("completed") // "completed" | "cancelled" | "refunded"

  // 메모
  memo           String?  @db.Text

  // 관리자 정보
  registeredBy     String  // 등록한 관리자 ID
  registeredByName String  // 등록한 관리자 이름

  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt

  @@index([userId])
  @@index([paymentDate])
  @@index([status])
  @@map("ad_automation_payments")
}
```

### 4. 제작물 완료 현황 (기존 Workflow 활용)

기존 Workflow 테이블의 status 필드를 활용하여 완료 여부 판단:
- `발송완료` = 완료 ✅
- 그 외 = 미완료 ❌

## 주요 특징

### 1. 시점 기록 중심
- 광고자동화 **기능 자체는 구현하지 않음**
- 관리자가 켜짐/꺼짐 상태만 **수동으로 토글**
- 모든 변경 사항은 **이력에 기록**

### 2. 마케팅 지원 기간 참조
- 마케팅 지원 종료일을 기본 종료일로 **참조만** 함
- 자동 연동이나 자동 종료 없음
- 관리자가 직접 확인하고 수동으로 관리

### 3. 간단한 결제 기록
- 유료 전환 시 결제일만 기록
- 서비스 기간은 계산하여 표시만
- 실제 결제 처리는 별도 시스템에서 진행

## 예상 질문 & 답변

**Q: 광고자동화 기능도 구현하나요?**
A: 아니요, 이 시스템은 **시점 관리**만 합니다. 실제 광고자동화 기능은 별도로 진행됩니다.

**Q: 광고자동화를 켜면 실제로 무엇이 작동하나요?**
A: 이 시스템에서는 아무것도 작동하지 않습니다. 단순히 "켜짐" 상태를 기록하고 표시만 합니다. 실제 광고 기능은 별도 시스템에서 이 상태를 참조하여 작동합니다.

**Q: 마케팅 지원 종료일이 지나면 자동으로 꺼지나요?**
A: 아니요, 자동으로 꺼지지 않습니다. 관리자가 직접 확인하고 수동으로 끄거나 결제를 등록해야 합니다.

**Q: 유료 결제는 어떻게 관리하나요?**
A: 관리자가 수동으로 결제일과 금액만 기록합니다. 실제 결제 처리는 별도 시스템에서 진행됩니다.

**Q: 제작물 현황 표시는 어떻게 작동하나요?**
A: 기존 Workflow 테이블의 status를 참조하여, "발송완료"는 🟢(완료), 그 외는 🔴(미완료)로 표시합니다.
