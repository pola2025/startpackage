## 🔍 발견된 문제

### 1. 시안 확인 404 에러 (Critical)

**증상**:
- 모달에서 "시안 확인하기" 클릭 시 404 에러 발생
- 콘솔: `Failed to load resource: the server responded with a status of 404`

**원인**:
```typescript
// design-confirmation-modal.tsx:89
router.push(`/dashboard/workflows/${currentWorkflow.id}`);
```
- `/dashboard/workflows/[id]` 상세 페이지가 존재하지 않음
- 실제로는 `/dashboard/workflows/page.tsx`만 존재

**영향**:
- **모든 사용자가 시안을 확인할 수 없음** (핵심 기능 마비)
- 로그인 시 모달은 표시되지만 클릭 시 404

---

### 2. 시안컨펌 모달이 표시되지 않음 (Critical)

**증상**:
- 시안이 업로드되어도 로그인 시 모달이 뜨지 않음
- 사이드바 "제작 현황" 배지 카운트가 0으로 표시됨

**원인**:
```typescript
// api/workflows/pending-confirmation/route.ts:43
where: {
  status: "시안중",  // ❌ 잘못된 조건
}
```

**실제 필요한 상태**:
- 로고: `"시안컨펌요청"`
- 인쇄물: `"발주대기"`
- 홈페이지: `"제작 완료"`

**영향**:
- 사용자가 시안 업로드를 인지할 수 없음
- 제작현황 페이지로 직접 가야만 확인 가능

## 🛠️ 해결 방법

### 1. 404 에러 해결

**접근 방식**: 상세 페이지를 새로 만들지 않고, 제작현황 페이지에서 URL 파라미터로 특정 시안을 자동으로 여는 방식 선택

**변경사항**:

#### A. 모달 네비게이션 수정
```typescript
// components/ui/design-confirmation-modal.tsx
const handleConfirmDesign = () => {
  // 제작현황 페이지로 이동하고 해당 워크플로우 다이얼로그 자동 오픈
  router.push(`/dashboard/workflows?open=${currentWorkflow.id}`);
  handleClose();
};
```

#### B. 제작현황 페이지에 자동 오픈 기능 추가
```typescript
// app/dashboard/workflows/page.tsx
const [dialogOpen, setDialogOpen] = useState(false);

// URL 파라미터로 특정 워크플로우 다이얼로그 자동 오픈
useEffect(() => {
  const openWorkflowId = searchParams.get("open");
  if (openWorkflowId && workflows.length > 0) {
    const workflow = workflows.find((w) => w.id === openWorkflowId);
    if (workflow) {
      setSelectedWorkflow(workflow);
      setDialogOpen(true);
      // URL 파라미터 제거 (깔끔하게)
      router.replace("/dashboard/workflows", { scroll: false });
    }
  }
}, [searchParams, workflows, router]);
```

#### C. Dialog 상태 관리 개선
```typescript
<Dialog
  open={selectedWorkflow?.id === workflow.id && dialogOpen}
  onOpenChange={(open) => {
    if (!open) {
      setDialogOpen(false);
      setSelectedWorkflow(null);
      setFeedbackText("");
    }
  }}
>
```

## 💡 배운 점

### 1. 404 에러는 항상 파일 구조부터 확인
- 처음에는 라우팅 문제인 줄 알았으나, 실제로는 **파일이 존재하지 않는 것**이 원인
- `ls` 명령어로 폴더 구조를 먼저 확인하는 습관 필요

### 2. API 상태 조건은 실제 사용처와 일치해야 함
- `pending-confirmation` API가 `"시안중"` 상태만 조회했는데
- 실제 UI(`workflows/page.tsx:377`)에서는 다른 상태들을 사용
- **코드 전체를 읽고 일관성을 확인해야 함**

### 3. URL 파라미터를 활용한 Deep Linking
- 상세 페이지를 만들지 않고도 특정 콘텐츠를 직접 열 수 있음
- `router.replace()`로 파라미터를 제거하면 URL이 깔끔해짐
- 사용자 경험 측면에서 더 자연스러움

### 4. Dialog 상태 관리
- `open` prop을 직접 제어하면 여러 Dialog 중 하나만 열 수 있음
- `selectedWorkflow?.id === workflow.id && dialogOpen` 조건으로 정확한 제어
