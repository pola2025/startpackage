# bas_mkt 작업 폴더 — 에이전트 안내

이 문서는 `C:\bas_mkt` 폴더에서 일하는 AI 에이전트(VS Code 터미널의 Codex, ChatGPT 앱의 Codex)가 읽는 문서입니다. ChatGPT 앱은 시작 메뉴에 "ChatGPT"로 표시되는 데스크톱 앱(패키지 `OpenAI.Codex`)입니다.
에이전트는 브라우저 자동화 환경을 스스로 점검하고 설치합니다. 사람이 해야 하는 단계에 이르면 멈추고 사람에게 요청합니다.
사람에게 이 문서의 내용을 설명하거나 절차를 가르치지 않습니다. 필요한 행동 한 가지만 짧게 요청합니다.

---

## 0. 처음 받았을 때

사람이 이 키트(`bas_mkt-agent-kit.zip`)를 전달하면 아래 1~8단계를 진행합니다. 단계마다 결과를 확인한 뒤 다음 단계로 넘어갑니다.

1. 압축 파일을 `C:\bas_mkt`에 풉니다. `C:\bas_mkt\AGENTS.md`, `C:\bas_mkt\rules`, `C:\bas_mkt\tools\naver-session`, `C:\bas_mkt\tools\blog`, `C:\bas_mkt\tools\meta`가 생겼는지 확인합니다. 같은 이름의 파일이 이미 있으면 덮어쓰기 전에 사람에게 확인합니다.
2. §2 환경 점검을 실행하고 표로 보고합니다.
3. 없는 도구만 §3에서 설치하고 §3.1 브라우저 자동화 패키지와 §3.2 웹 조사 도구(insane-search)를 준비합니다.
4. §1의 "ChatGPT 앱 로그인", "ChatGPT 앱 컴퓨터 사용 설정", "ChatGPT 앱 브라우저 설정"을 하나씩 사람에게 요청합니다.
5. `C:\bas_mkt\.private\browser-profiles`에 `naver-*` 폴더가 있는지 먼저 확인합니다. 있으면 그 이름을 계정 이름으로 쓰고, 없을 때만 사람에게 네이버 계정 이름으로 쓸 영문 이름 한 가지를 묻습니다(예: `myblog`). 비밀번호는 묻지 않습니다.
6. `node check.mjs <계정>`을 실행합니다. 결과가 2이면 `bootstrap.mjs`를 실행하고 §1의 "네이버 첫 로그인"을 요청합니다.
7. 첫 로그인 후 24시간이 지났으면 §5.2의 매일 자동 연장을 등록합니다. 24시간이 지나기 전이면 기다리지 않고 다음 단계로 넘어갑니다. 나중에 `check.mjs`가 "매일 연장 미등록"을 출력하면 그때 등록합니다.
8. 첫 글을 발행하기 전에 §1의 "블로그 기본 설정"이 끝났는지 사람에게 확인합니다.
9. §6.0을 진행합니다(글 도구 설치, 회사 정보 등록).

에이전트가 절대 하지 않는 일:

- 네이버 비밀번호를 묻거나 받지 않습니다. 사람이 보냈다면 사용하지 말고 삭제를 요청합니다.
- 비밀번호·쿠키 값·프로필 폴더 내용을 채팅, 로그, 파일, 커밋에 남기지 않습니다.
- 로그인 폼에 아이디·비밀번호를 대신 입력하지 않습니다.
- ChatGPT 앱의 사이드 탭(앱 안 브라우저)으로 네이버 블로그 작업을 하지 않습니다. 네이버 블로그 작성은 사이드 탭에서 차단됩니다.
- 네이버 로그인·글쓰기·예약 확인·예약 삭제에 ChatGPT 앱의 컴퓨터 사용, Chrome 확장, browser-use, insane-search를 쓰지 않습니다. 네이버 작업은 §5 도구로만 합니다. 전용 프로필 폴더를 `chrome.exe --user-data-dir` 같은 방법으로 직접 열지 않고, 사람이 평소 쓰는 Chrome의 네이버 로그인 칸도 건드리지 않습니다.
- 블로그 기본 설정(블로그명·주소·배경·프로필·레이아웃·메뉴·위젯)을 바꾸지 않습니다. 사람이 직접 합니다.
- 네이버에 예약했거나 올라간 글을 고치지 않습니다. 편집기에서 고치는 것도, 예약을 지우고 고친 글을 다시 올리는 것도 하지 않습니다. 에이전트가 네이버 글을 고치면 실패할 때가 많고 자동 수정으로 문제가 생길 수 있습니다. 사람이 수정을 요청하면 §1의 "글 수정" 요청 문장을 보냅니다.
- 사람의 "발행" 답 없이 글을 발행하지 않습니다. 사람이 "확인 없이 올려도 된다"고 직접 말한 경우에만 승인 단계를 건너뜁니다.
- 사람의 "게재 시작" 답 없이 광고를 켜지 않습니다. 광고는 모두 꺼진 상태로 만들고, 켜는 일은 `ads.mjs launch`로만 합니다.

### 3.2 웹 조사 도구 (insane-search)

일반 요청으로 열리지 않는 공개 페이지(네이버 블로그 글, 쿠팡, 링크드인, X, 유튜브 자막 등)를 읽을 때 쓰는 Codex 스킬입니다. 이 키트에는 파일이 들어 있지 않습니다. 에이전트가 원본 저장소(https://github.com/fivetaku/insane-search, MIT 라이선스)에서 받아 설치합니다. Git과 Python이 먼저 설치되어 있어야 합니다.

```powershell
$env:Path = [Environment]::GetEnvironmentVariable('Path','Machine') + ';' + [Environment]::GetEnvironmentVariable('Path','User')
$src = "$env:TEMP\insane-search-src"
if (Test-Path $src) { Remove-Item $src -Recurse -Force }
git clone --depth 1 https://github.com/fivetaku/insane-search.git $src
$dst = "$env:USERPROFILE\.codex\skills\insane-search"
New-Item -ItemType Directory -Force (Split-Path $dst) | Out-Null
if (Test-Path $dst) { Remove-Item $dst -Recurse -Force }
Copy-Item "$src\skills\insane-search" $dst -Recurse
python -m pip install -U "curl_cffi>=0.15.0" beautifulsoup4 pyyaml yt-dlp
cd $dst
python -m engine "https://example.com"
```

- 마지막 명령의 출력 어딘가에 `[engine] ok=True`가 있으면 설치가 끝난 것입니다. PowerShell에서는 이 줄이 본문보다 늦게 나올 수 있습니다. 이미 설치되어 있으면 같은 명령으로 최신 버전으로 바꿉니다.
- 스킬 목록에는 다음 Codex 세션부터 나타납니다. 지금 세션에서는 스킬 폴더에서 `python -m engine "<주소>"`를 직접 실행합니다.

이 스킬의 SKILL.md는 Claude Code 기준으로 쓰여 있습니다. Codex에서는 아래처럼 바꿔 씁니다.

- SKILL.md의 Step 0(`setup.sh`, GitHub 별점 질문)은 실행하지 않습니다.
- `python3` 대신 `python`을 씁니다. 엔진은 항상 스킬 폴더(`$env:USERPROFILE\.codex\skills\insane-search`)에서 실행합니다.
- 결과에 `must_invoke_playwright_mcp`가 나오면 Codex에서 쓸 수 없는 경로입니다. 멈추고 어떤 주소였는지 보고합니다.
- Playwright 템플릿이 필요하다고 나올 때만 `engine\templates` 폴더에서 `npm.cmd install`을 실행합니다.

쓰는 범위:

- 공개된 페이지를 읽는 데만 씁니다. 네이버 로그인·글쓰기·관리 화면에는 쓰지 않습니다. 네이버 작업은 §5 도구만 씁니다.
- 로그인이 필요한 페이지를 열거나 보안문자·차단을 풀려고 반복 시도하지 않습니다.

## 4. 네이버 로그인·발행 규칙

네이버는 봇을 행동 패턴으로 잡아냅니다. 아래 규칙은 하나도 어기지 않습니다. 어기면 보호조치와 보안문자가 걸리고 자동화가 멈춥니다.

1. **아이디·비밀번호 입력은 사람이 첫 로그인(부트스트랩)에서만 합니다.** 에이전트는 창을 열고 기다리기만 합니다. 첫 로그인은 그 노트북을 평소 쓰는 회사·집 네트워크에서 합니다. 교육장·카페 와이파이는 피합니다.
2. **성공 여부는 쿠키로 판정합니다.** `NID_AUT`가 영속 쿠키(만료일이 있는 쿠키)여야 성공입니다. 로그인 화면이 넘어간 것만으로는 성공이 아닙니다.
3. **세션 상태는 `check.mjs`로만 판단합니다.** 로그인 폼을 열어 보고 판단하지 않습니다. 지금의 네이버 로그인 주소는 세션이 살아 있어도 폼을 보여 줍니다.
4. **무인 실행에서 세션이 없으면 멈추고 사람에게 알립니다.** 자동으로 다시 로그인하지 않습니다.
5. **같은 날 짧은 간격으로 다시 로그인하지 않습니다.** 로그인이 실패했거나 세션이 사라졌다면 다음 날 사람이 다시 로그인합니다.
6. **세션 연장(터치)은 첫 로그인 후 24시간이 지나서 시작합니다.** 갓 로그인한 세션에 터치를 걸면 세션이 사라집니다.
7. **터치 뒤 `NID_AUT`가 사라지면 그날은 아무것도 하지 않습니다.** 이때 다시 로그인하면 보호조치로 이어집니다.
8. **계정마다 전용 프로필 하나만 씁니다.** 경로는 `C:\bas_mkt\.private\browser-profiles\naver-<계정>`입니다. 매번 새 프로필을 만들지 않습니다.
9. **프로필 폴더를 다른 PC로 복사하지 않습니다.** 쿠키가 Windows 계정으로 암호화되어 있어 다른 PC에서는 풀리지 않습니다. 옮겨야 하면 멈추고 사람에게 확인합니다.
10. **보안문자·보호조치를 우회하지 않습니다.** 시도할수록 잠금이 깊어집니다. 멈추고 사람에게 알립니다.
11. **로그인·발행 코드를 새로 짜지 않습니다.** 반드시 §5 도구를 씁니다. 도구로 해결되지 않는 상황이면 멈추고 보고합니다.
    - 금지: `page.fill`로 아이디·비밀번호 채우기, `Enter`로 제출, 대기 중 `page.goto`로 페이지 새로 고침.
12. **네이버 블로그에는 절대 복사·붙여넣기로 입력하지 않습니다.** 클립보드 붙여넣기, `insertText`, 편집기 화면에 값을 직접 넣는 방식은 모두 금지입니다. 붙여 넣은 글은 자동 입력으로 감지될 수 있습니다. 제목과 본문은 `publish.mjs`가 한 글자씩 입력합니다. 사람에게도 원고를 복사해 네이버에 붙여 넣으라고 안내하지 않습니다.
13. **기본은 예약 발행입니다.** `publish.mjs`는 글을 입력한 뒤 3시간 뒤로 예약하고, 같은 계정의 다른 예약과는 3시간 이상 떨어뜨립니다. 예약 시각이 밤 11시부터 아침 7시 사이에 걸리면 아침 8시대로 옮깁니다. 사람이 시각을 정하면 `--at`을 붙이고, 사람이 바로 올려 달라고 직접 말한 경우에만 `--now`를 붙입니다.
14. **계정 이름을 바꾸지 않습니다.** 프로필 폴더(`naver-<계정>`)가 이미 있으면 그 이름을 계속 씁니다. 사람에게 다시 묻거나 블로그 주소로 새 이름을 만들면 프로필이 둘로 갈라지고, 연장 작업이 다른 프로필을 연장해 세션이 끊깁니다. `naver-*` 폴더가 둘 이상이면 멈추고 어느 것을 쓸지 사람에게 묻습니다.
15. **같은 글은 하루 두 번까지만 실행합니다.** 네이버 화면을 여는 명령(`publish.mjs` 본 실행, `bootstrap.mjs`)은 같은 글·같은 계정에 하루 2번을 넘기지 않습니다. 실패를 반복 실행하면 행동 패턴으로 잡혀 보호조치로 이어집니다. §5.1 표에 없는 코드가 나오면 다시 실행하지 않고, 출력 마지막 20줄과 `.private\logs\publish-<글폴더>.log`를 보고합니다.
16. **네이버 명령은 한 번에 하나, 한 곳에서만 실행합니다.** VS Code의 Codex와 ChatGPT 앱에서 동시에 실행하지 않습니다. 계정이 둘이어도 발행은 한 편씩 합니다. `check.mjs`만 예외입니다.
17. **편집기의 꾸미기 기능은 쓰지 않습니다.** 소제목 서식, 굵게, 밑줄, 기울임, 글자 크기·색, 인용구 같은 기능은 에이전트가 쓰면 될 때와 안 될 때가 있어 오류가 잦습니다. 글은 문단 입력, 이미지, 이미지 링크, 태그만으로 만들고, 소제목은 소제목 이미지로 대신합니다. 사람이 꾸미기를 요청하면 직접 하도록 안내합니다: "굵게·밑줄 같은 꾸미기는 글이 올라간 뒤 수정 화면에서 직접 하시는 것이 가장 빠르고 정확합니다."

## 5. 세션·발행 도구 (`C:\bas_mkt\tools\naver-session`)

`<계정>`은 영문 이름입니다(예: `myblog`). 계정마다 같은 이름을 계속 씁니다.

| 명령 | 언제 | 하는 일 |
| --- | --- | --- |
| `node check.mjs <계정>` | 모든 작업 전 | 프로필 쿠키만 읽어 세션 상태를 알려 줍니다. 페이지를 열지 않습니다. |
| `node bootstrap.mjs <계정>` | 세션이 없을 때, 사람이 옆에 있을 때만 | 전용 프로필로 로그인 창을 열고 "로그인 상태 유지"를 켠 뒤 사람이 로그인할 때까지 쿠키만 확인합니다. |
| `node touch.mjs <계정>` | 첫 로그인 24시간 뒤부터 하루 1번 | 네이버 내정보 경로를 한 번 열어 세션 만료일을 연장합니다. |
| `node publish.mjs <계정> <글폴더> --check` | 발행 전 | 원고 형식을 검사하고 글폴더에 `preview.html`을 만듭니다. 브라우저를 열지 않습니다. |
| `node publish.mjs <계정> <글폴더>` | 사람이 "발행"이라고 답한 뒤 | 전용 프로필로 글쓰기 화면을 열어 제목·본문을 한 글자씩 입력하고 이미지·태그를 넣습니다. 입력이 끝나면 편집기의 제목·문단·이미지 수를 원고와 대조하고, 하나라도 다르면 발행하지 않고 멈춥니다. 맞으면 3시간 뒤(같은 계정의 다른 예약과 3시간 이상 떨어진 시각)로 예약하고, 예약 목록에서 제목과 시각을 확인합니다. 입력에 10분 정도 걸립니다. |
| `node publish.mjs <계정> <글폴더> --at "2026-10-18 09:30"` | 사람이 예약 시각을 정했을 때 | 그 시각(한국 시간, 10분 단위로 올림)으로 예약합니다. 지금부터 30분 이후여야 합니다. |
| `node publish.mjs <계정> <글폴더> --now` | 사람이 바로 올려 달라고 직접 말했을 때만 | 예약 없이 바로 발행하고 공개 글에서 제목을 확인합니다. |
| `node publish.mjs <계정> <글폴더> --dry-run` | 사람이 "발행하지 말고 시험만 해 봐"라고 할 때 | 입력·대조·태그·예약 시각 설정까지 진행하고 마지막 발행 버튼만 누르지 않습니다. 발행 기록을 남기지 않습니다. 입력한 글은 네이버 임시저장 목록에 남을 수 있습니다. |
| `node publish.mjs <계정> <글폴더> --repost` | 사람이 예약을 삭제했다고 답한 뒤 같은 글을 그대로 다시 예약해 달라고 할 때만(§5.3) | 내 컴퓨터의 발행 기록이 막는 것만 건너뜁니다. 네이버 예약 목록이나 공개 글에 같은 제목이 남아 있으면 그대로 막습니다. |

### 5.1 결과 코드

| 코드 | 뜻 | 에이전트의 다음 행동 |

### 5.2 매일 자동 연장 등록

`check.mjs` 결과가 0이고 첫 로그인 후 24시간이 지났을 때만 등록합니다. `check.mjs`는 이 조건에서 작업이 등록되어 있지 않으면 "매일 연장 미등록" 줄을 출력합니다. 이 줄을 보면 하던 작업을 이어가기 전에 먼저 등록합니다.

```powershell
schtasks /Create /SC DAILY /ST 09:10 /TN "bas_mkt-naver-touch-<계정>" /TR "cmd /c cd /d C:\bas_mkt\tools\naver-session && node touch.mjs <계정>" /F
```

- 실행 기록은 `C:\bas_mkt\.private\logs\naver-touch-<계정>.log`에 쌓입니다. 작업을 시작할 때 마지막 줄을 읽습니다. `실패`나 `중단`이 있으면 먼저 보고합니다.
- 09:10 전후에는 연장 작업이 프로필을 쓰므로 발행을 피합니다.
- 등록한 다음 작업부터 `schtasks /Query /TN "bas_mkt-naver-touch-<계정>" /V /FO LIST`로 '마지막 실행 시간'을 확인합니다. 노트북이 09:10에 꺼져 있어 한 번도 실행되지 않았다면, 사람에게 PC를 켜 두는 시각을 물어 `/ST`를 그 시각으로 바꿔 다시 등록합니다. 발행을 실행하는 시각과는 30분 이상 떨어뜨립니다.

### 5.3 예약 글 취소·수정

- 예약했거나 올라간 글을 고치는 일은 사람이 네이버에서 직접 합니다. 에이전트는 원고를 고쳐 다시 올리지 않고 §1의 "글 수정" 요청 문장을 보냅니다.
- 예약을 취소할 때도 에이전트가 브라우저로 처리하지 않습니다. §1의 "예약 취소" 요청 문장을 보내고 기다립니다.
- 사람이 예약을 지운 뒤 같은 글을 고치지 않고 그대로 다시 예약해 달라고 직접 요청한 경우에만 `publish.mjs ... --repost`를 씁니다.
- 발행 기록 파일(`naver-published-<계정>.jsonl`)은 고치거나 지우지 않습니다.

## 6. 블로그 글 만들기 (기업마당 공고)

사람이 기업마당 주소를 주면 공고를 고르고, 사실을 확인받고, 원고와 이미지를 만든 뒤 검수를 받아 발행합니다. 글 내용 규칙은 `C:\bas_mkt\rules\blog-gov-news.md`에 있습니다. 원고를 쓰기 전에 반드시 읽습니다.

사람이 하는 일은 공고 번호 고르기, 사실 카드 확인, 검수 후 발행 답하기 세 가지뿐입니다. 그 사이의 조사·원고·이미지·검사는 에이전트가 끝까지 진행합니다.

### 6.0 처음 한 번 준비

1. 글 도구를 설치합니다.
   ```powershell
   cd C:\bas_mkt\tools\blog
   npm.cmd install
   ```
2. `C:\bas_mkt\brand.json`이 없으면 §1의 "회사 정보" 요청 문장을 보내고, 받은 답으로 아래 파일을 만듭니다. 로고 파일을 받으면 `C:\bas_mkt\brand\logo.png`로 복사합니다(png·jpg). 없으면 `logo`를 빈 문자열로 둡니다.
   ```json
   {
     "company": "OO경영컨설팅",
     "phone": "055-000-0000",
     "homepage": "https://oo-consulting.co.kr",
     "color": "#285EC0",
     "logo": "brand/logo.png",
     "cta": "A"
   }
   ```
   - `homepage`는 `https://`로 시작해야 합니다. CTA 이미지에 이 주소로 링크가 걸립니다.
   - `color`는 `#`과 여섯 자리 색 코드입니다. 사람이 "파란색"처럼 말하면 가까운 진한 색 코드로 정하고 알려 줍니다.
   - `cta`는 CTA 디자인입니다. `A` 상담 연결형(기본), `B` 체크리스트형, `C` 티켓형 중 사람이 고른 것을 넣습니다.

### 6.1 순서

사람이 기업마당 주소가 든 요청을 보내면 아래 1~12단계를 진행합니다. 명령은 모두 `C:\bas_mkt\tools\blog`에서 실행합니다.

1. **후보 고르기**
   - 주소가 목록이면 `node bizinfo.mjs list "<주소>"`를 실행합니다. 공고 상세 주소(`pblancId=`가 들어 있음)면 이 단계를 건너뜁니다.
   - 이미 글을 쓴 공고(`C:\bas_mkt\posts\*\source\notice.json`에 같은 공고 번호가 있는 것)는 후보에서 뺍니다. 같은 공고로 비슷한 글을 다시 올리면 반복 글로 보일 수 있습니다.
   - 출력에서 접수 중인 공고 가운데 사람이 말한 분야(정책자금·지원사업·소상공인·창업 등)에 맞는 것을 5개까지 골라 표로 보여 줍니다. 열: 번호, 사업명, 기관, 신청기간, 분야, 글감(첨부 공고문이 있으면 "충분", 없으면 "부족").
   - §1의 "공고 고르기" 요청 문장을 보내고 기다립니다.
2. **원문 수집**
   - 글폴더 이름을 정합니다: `C:\bas_mkt\posts\<YYYYMMDD>-<영문-글이름>`(영문 소문자·숫자·하이픈).
   - `node bizinfo.mjs get "<공고 주소 또는 PBLN_번호>" <글폴더>`를 실행합니다. 공고 요약은 `source\notice.json`, 본문과 첨부 공고문 텍스트는 `source\source.txt`에 저장됩니다.
   - 출력에 "읽지 못한 첨부"가 있으면 그 파일을 다른 방법으로 열어 텍스트를 `source\` 안의 `.txt` 파일로 저장합니다. 끝내 못 읽으면 공고 요약만으로 진행하고 그 사실을 사람에게 알립니다.
3. **사실 카드**
   - `facts.json`을 씁니다(§6.2). 모든 항목의 `quote`는 `source\` 안 텍스트 파일의 문장을 한 글자도 바꾸지 않고 옮깁니다.
   - 공고 내용만으로 본문 2,800자를 채우기 어렵다고 판단되면 관련 기사·정부 발표를 찾습니다(§3.2 웹 조사 도구). 2025년의 흐름, 2026년에 달라진 점, 앞으로의 전망을 다룬 자료를 고릅니다. 읽은 본문을 `source\ext-1.txt`처럼 저장하고 `sources.json`에 적습니다(§6.2).
   - `node check.mjs <글폴더> --facts`를 실행합니다. 통과하면 글폴더에 `facts.html`이 생깁니다.
   - §1의 "사실 카드 확인" 요청 문장을 보내고 기다립니다. 사람이 고칠 점을 말하면 고치고 다시 실행합니다.
4. **원고**: `rules\blog-gov-news.md`를 읽고 `plan.json`을 씁니다(§6.2).
5. **실사 이미지**
   - 내장 이미지 생성 기능으로 `photos\cover.png`(표지 배경)와 `photos\photo-1.png`~`photo-5.png`(본문 실사 4~5장)를 만듭니다.
   - 4:3 가로, 한국 업무현장, 글자·숫자·로고·간판 없음, 인물 얼굴이 주인공이 되지 않게(뒷모습·옆모습·어깨 너머) 만듭니다. 장면은 그 공고의 업종과 절차에 맞춥니다.
   - 생성된 파일은 `%USERPROFILE%\.codex\generated_images` 아래에 저장됩니다. 이번에 새로 생긴 파일인지 수정 시각으로 확인한 뒤 복사합니다. 이전 이미지를 다시 쓰지 않습니다.
6. **이미지 조립**: `node build.mjs <글폴더>`를 실행합니다. 표지·카드·소제목·차트·CTA 이미지를 `out\`에 만들고 `post.json`과 검수 화면 `review.html`을 씁니다.
7. **검사**: `node check.mjs <글폴더>`를 실행합니다. 실패 항목이 있으면 `plan.json`을 고치고 6~7을 다시 실행합니다. 통과할 때까지 사람에게 넘기지 않습니다.
   - 출력은 마지막 줄만 보지 않습니다. ❌ 줄과 ⚠ 줄을 모두 찾아 확인합니다.
   - ⚠ 가운데 "첫 문장이 다른 글과 같습니다", "검색 결과 미리보기에서 작게 보입니다"는 고친 뒤 넘어갑니다. 표지 `accent`, 카드 `lines`, 소제목도 이전 글과 같은 문구를 쓰지 않습니다.
8. **형식 검사**: `node ..\naver-session\publish.mjs <계정> <글폴더> --check`를 실행합니다.
9. **검수 요청**: `review.html`을 열어 표지·카드·차트 글자가 잘리지 않았는지 직접 확인합니다. 표지·카드·소제목·CTA 이미지의 마지막 줄에 한두 글자만 떨어져 있으면 문구를 바꿔 다시 만듭니다. 그다음 §1의 "발행 승인" 요청 문장을 보내고 기다립니다.
10. **수정**: 발행 전 검수 단계에서 사람이 고칠 곳을 말하면 고친 뒤 6번부터 다시 실행합니다. 실사를 다시 만들 때는 그 장면 한 장만 다시 만듭니다. 네이버에 예약했거나 올라간 뒤의 수정 요청은 §5.3을 따릅니다.
11. **발행**: 사람이 "발행"이라고 답하면 `node ..\naver-session\check.mjs <계정>`으로 세션을 확인합니다. §1의 "발행 중 대기" 요청 문장을 보낸 뒤 `node ..\naver-session\publish.mjs <계정> <글폴더>`를 실행합니다. 결과 코드가 0이면 예약 시각을 보고하고, 그 밖의 코드는 §5.1대로 행동합니다.
12. **발행 확인**: 예약 시각이 지난 뒤 다음 작업을 시작할 때 확인합니다.
    - 발행 기록(`C:\bas_mkt\.private\logs\naver-published-<계정>.jsonl`)의 `logNo`로 공개 페이지 `https://m.blog.naver.com/<블로그아이디>/<logNo>`를 받아(로그인하지 않음) 제목과 본문 첫 문단이 있는지 확인합니다. 없거나 열리지 않으면 고치지 말고 보고합니다.
    - 발행 다음 날에는 네이버 블로그 탭에서 제목 전체로 검색해 글이 보이는지 확인합니다. 보이지 않으면 사람에게 알립니다. 검색반영 신청은 사람이 지시했을 때만 합니다. 신청은 취소할 수 없습니다.

### 6.2 글폴더 파일

```
posts\20261017-changwon-sme-fund\
  source\notice.json  source\notice.html  source\source.txt  source\<첨부>  source\ext-1.txt
  facts.json  sources.json  plan.json
  photos\cover.png  photos\photo-1.png … photo-5.png
  out\*.png  post.json  facts.html  review.html   ← 도구가 만듭니다
```

`facts.json`: 공고에서 확인한 사실입니다. 원고의 숫자와 고유명사는 여기서만 가져옵니다.

```json
{
  "program": "2026년 창원시 중소기업 육성자금 융자지원 계획",
  "names": ["2026년 창원시 중소기업 육성자금 융자지원 계획", "창원시", "창원시 지역경제과"],
  "sourceLabel": "2026년 창원시 중소기업 육성자금 융자지원 계획 공고(창원시)",
  "items": [
    { "key": "접수기간", "value": "2026. 1. 2.(금) ~ 자금 소진 시까지", "quote": "접수기간 : 2026. 1. 2.(금) ~ 자금 소진 시까지" }
  ]
}
```

- `program`은 공고문에 적힌 사업명 그대로입니다. `names`에는 사업명·소관 기관·수행 기관·문의 부서처럼 글에 그대로 써야 하는 이름을 넣습니다.
- `items`에는 지원 대상, 제외 대상, 지원 규모, 지원 내용(금리·한도·비율), 신청 기간, 신청 방법, 제출 서류, 문의처, 유의사항을 공고에 있는 만큼 넣습니다.

`sources.json`: 공고 밖에서 가져온 자료입니다. 없으면 빈 배열 `[]`로 둡니다.

```json
[
  { "title": "기사 또는 발표 제목", "publisher": "매체·기관명", "date": "2026-03-02", "url": "https://…", "file": "source/ext-1.txt", "quotes": ["본문에서 그대로 옮긴 문장"] }
]
```

`plan.json`: 원고입니다. `build.mjs`가 이 파일로 이미지와 `post.json`을 만듭니다.

```json
{
```

## 7. Meta SNS 자동화 (인스타그램 · 페이스북 페이지 · 쓰레드)

Meta 연결(앱, 시스템 사용자, 쓰레드 토큰 발급)은 폴라애드에서 미리 끝냈습니다. 사람은 메일로 받은 **시스템사용자 토큰**과 **쓰레드 토큰** 두 값만 에이전트에게 줍니다. 콘텐츠 규칙은 `C:\bas_mkt\rules\sns-meta.md`에 있습니다. 게시물을 만들기 전에 반드시 읽습니다.

### 7.0 토큰 받기와 연결 검증

1. 사람이 두 토큰을 채팅에 붙여 넣으면 **경고하거나 거절하지 않습니다.** 사람 본인의 PC에서만 쓰는 값입니다. 바로 저장합니다.
2. `C:\bas_mkt\.env`에 아래 두 줄로 저장합니다(파일이 있으면 해당 줄만 바꿉니다). `C:\bas_mkt\.gitignore`에 `.env`가 있는지 확인합니다. 저장한 뒤에는 토큰 값을 다시 출력하지 않습니다.
   ```
   META_SYSTEM_USER_TOKEN=<시스템사용자 토큰>
   THREADS_ACCESS_TOKEN=<쓰레드 토큰>
   ```
3. 연결을 검증합니다. 출력 첫 줄을 그대로 보고한 뒤 §1의 "계정 확인" 요청 문장을 보냅니다.
   ```powershell
   cd C:\bas_mkt\tools\meta
   node check.mjs
   ```

| 코드 | 뜻 | 다음 행동 |
| --- | --- | --- |
| 0 | 연결 정상 | 계정 이름을 보여 주고 확인을 받습니다. |
| 2 | `.env`에 토큰이 없음 | 빠진 값을 사람에게 다시 받습니다. |
| 3 | 권한 부족 | 빠진 권한 이름을 그대로 전하고 폴라애드에 문의하도록 안내합니다. |
| 4 | 페이지가 여러 개 | 출력된 목록을 보여 주고 어느 페이지인지 묻습니다. 답을 받으면 `node check.mjs --page <id>` |
| 5 | 페이지가 없거나 인스타 미연결 | 교육 03·04장(인스타그램 계정, 계정 통합)을 다시 확인하도록 안내합니다. |

### 7.1 인스타그램 + 페이스북 페이지 (동시 게시)

게시폴더는 `C:\bas_mkt\sns\<YYYYMMDD>-<영문-이름>`입니다. 안에 `sns.json`과 이미지·영상 파일이 들어갑니다.

```json
{ "type": "carousel", "files": ["cards/01.png", "cards/02.png"], "caption": "모바일 폭 캡션" }
```

`type`은 `carousel`(이미지 2~10장), `image`(1장), `reels`(세로 영상 1개)입니다.

**A. 블로그 글로 카드뉴스 만들기**
1. `cd C:\bas_mkt\tools\blog` 후 `node cards.mjs <글폴더>`를 실행합니다. 1080×1440 카드가 `C:\bas_mkt\sns\<글폴더 이름>\cards\`에 생기고 `sns.json`이 만들어집니다.
2. `rules\sns-meta.md` §5대로 캡션을 써서 `sns.json`의 `caption`에 넣습니다. 숫자·사업명은 그 글의 `facts.json` 값만 씁니다.
3. 아래 C로 이어갑니다.

**B. 사람이 준 이미지·영상 올리기**
1. 받은 파일을 게시폴더에 복사합니다. 원본 파일은 옮기거나 고치지 않습니다.
2. `node size.mjs <게시폴더>`로 크기를 점검합니다. ❌가 있으면 `rules\sns-meta.md` §4대로 사람에게 알리고 기다립니다.
3. `sns.json`을 쓰고(이미지 여러 장은 `carousel`, 영상은 `reels`), 캡션을 씁니다. 사람이 캡션을 줬으면 내용은 바꾸지 않고 모바일 폭 줄바꿈과 이모지만 다듬습니다.

**C. 검수와 게시**
1. `cd C:\bas_mkt\tools\meta` 후 `node publish.mjs <게시폴더> --check`를 실행합니다. ❌는 고치고, ⚠도 고칠 수 있으면 고친 뒤 다시 실행합니다.
2. 만들어진 `review.html`을 열어 글자 잘림을 직접 확인한 뒤 §1의 "SNS 게시 승인" 요청 문장을 보냅니다.
3. 사람이 "게시"라고 답하면 `node publish.mjs <게시폴더>`를 실행합니다. 이미지는 페이지에 비공개로 먼저 올리고, 페이지가 돌려준 이미지 주소로 인스타그램 게시물을 만든 뒤, 페이지에도 같은 내용을 게시합니다.
4. 결과 코드 0이면 출력된 인스타·페이지 주소를 전하고 §1의 "게시 확인" 요청 문장을 보냅니다.

| 코드 | 뜻 | 다음 행동 |
| --- | --- | --- |
| 0 | 두 채널 모두 게시·확인 | 주소를 전하고 사람에게 앱에서 확인해 달라고 요청합니다. |
| 8 | 이미 올린 게시물 | 다시 올리지 않습니다. 기존 주소를 전합니다. |

`--dry-run`은 페이지 비공개 업로드와 인스타 게시 준비까지만 하고 아무것도 공개하지 않습니다. 사람이 "시험만 해 봐"라고 할 때 씁니다.

### 7.2 쓰레드 (그날 올릴 글을 그날 설정)

인스타그램·쓰레드 API에는 예약 게시 기능이 없고, 글은 이 PC가 켜져 있을 때만 올라갑니다. 그래서 **그날 올릴 글만 그날 설정**합니다. 다른 날짜로 예약하거나 미리 써 둔 글을 여러 날에 나눠 올려 달라는 요청을 받으면, 하지 않고 이렇게 안내합니다: "인스타그램·쓰레드는 API로 예약할 수 없고 PC가 켜져 있어야 올라갑니다. 예약이나 미리 작성한 글을 나눠 올리는 방식은 폴라애드 고급과정 개별교육에서 다룹니다."

1. 사람이 컨셉을 말하면 `rules\sns-meta.md` §6의 기본값과 합쳐 `C:\bas_mkt\threads-concept.md`에 정리합니다(독자, 말투, 다룰 주제, 넣지 않을 것).
2. 컨셉대로 오늘 올릴 4편을 써서 보여 주고 §1의 "쓰레드 샘플 확인" 요청 문장을 보냅니다. 고칠 점을 말하면 반영해 다시 보여 줍니다.
3. "확인"을 받으면 4편을 JSON 파일(예: `C:\bas_mkt\sns\threads-<YYYYMMDD>.json`)로 쓰고 `node threads.mjs add <파일>`로 대기열에 넣습니다. 규칙 위반이 하나라도 있으면 하나도 들어가지 않으니, 출력대로 고친 뒤 다시 넣습니다. 대기열의 글은 넣은 날에만 올라가고, 그날 못 올린 글은 다음 날 자동으로 빠집니다.
4. 시각별 실행 작업이 없으면 등록합니다(처음 한 번). PC가 켜져 있는 동안 08:00 · 11:30 · 15:00 · 18:30에 한 편씩 올립니다. 사람이 "지금 올려 줘"라고 하면 `node threads.mjs run`으로 바로 한 편을 올립니다.
   ```powershell
   schtasks /Create /SC DAILY /ST 08:00 /TN "bas_mkt-threads-1" /TR "cmd /c cd /d C:\bas_mkt\tools\meta && node threads.mjs run" /F
   schtasks /Create /SC DAILY /ST 11:30 /TN "bas_mkt-threads-2" /TR "cmd /c cd /d C:\bas_mkt\tools\meta && node threads.mjs run" /F
   schtasks /Create /SC DAILY /ST 15:00 /TN "bas_mkt-threads-3" /TR "cmd /c cd /d C:\bas_mkt\tools\meta && node threads.mjs run" /F
   schtasks /Create /SC DAILY /ST 18:30 /TN "bas_mkt-threads-4" /TR "cmd /c cd /d C:\bas_mkt\tools\meta && node threads.mjs run" /F
   ```
5. `node threads.mjs status`로 대기 수를 보고하고 §1의 "쓰레드 게시 확인" 요청 문장을 보냅니다.
6. 작업을 시작할 때 `.private\logs\threads-run.log` 마지막 줄을 읽습니다. "지난 날짜 글"이 있으면 PC가 꺼져 있어 못 올린 글이 있었다고 알립니다. "실패"가 있으면 그 줄을 보고합니다.

- 쓰레드 토큰은 60일마다 만료됩니다. `threads.mjs run`이 실행될 때마다 만료 30일 전부터 자동으로 갱신하고 `.env`를 바꿉니다. 사람이 할 일은 없습니다.
- 결과 코드: 0 게시, 8 이미 올린 글이라 건너뜀, 9 게시했지만 주소 확인 실패(다시 실행하지 않음), 10 규칙 위반, 11 API 오류, 13 실행 중, 15 오늘 올릴 글이 없어 게시 0건.
- 같은 글을 반복해서 올리지 않습니다. 자동 답글, 자동 좋아요·팔로우, 다른 계정 글에 댓글 달기는 하지 않습니다.

## 8. Meta 광고 자동화 (잠재 고객 광고 · 인스턴트 양식)

§7과 같은 시스템사용자 토큰을 씁니다. 표준 설정, 입력양식, 문구 규칙은 `C:\bas_mkt\rules\ads-meta.md`에 있습니다. 광고를 만들기 전에 반드시 읽습니다. 도구는 `C:\bas_mkt\tools\meta\ads.mjs`입니다. 캠페인·광고 세트·광고는 **모두 꺼진 상태(일시 중지)로 만들고** 사람이 "게재 시작"이라고 답한 뒤에만 켭니다.

### 8.0 광고 계정 점검 (처음 한 번)

1. §7.0 연결 검증(`node check.mjs`)이 끝나 있어야 합니다. 출력에 "광고 권한 없음"이 있으면 폴라애드에 문의하도록 안내합니다.
2. `cd C:\bas_mkt\tools\meta` 후 `node ads.mjs check`를 실행하고 출력 첫 줄을 그대로 보고합니다.
3. 잠재 고객 광고 약관과 차별 금지 정책 동의는 폴라애드가 미리 처리합니다. 사람에게 동의를 요청하지 않습니다.

| 2 | 계정 정보 없음 | `node check.mjs`부터 실행합니다. |
| 3 | 광고 권한 없음 | 빠진 권한 이름을 전하고 폴라애드에 문의하도록 안내합니다. |

| 16 | 광고 계정 비활성·미결제 | 출력된 상태를 전하고 광고 관리자의 계정 개요를 확인해 달라고 요청합니다. |

### 8.1 입력양식 만들기

사람은 교육 화면의 입력폼 요청 문장(양식 이름, 질문, 정보 취급 설명, 완료 화면 문구)을 그대로 보냅니다. 양식을 다시 확인받지 않고 그 문장대로 만듭니다.

1. 광고폴더 `C:\bas_mkt\ads\<YYYYMMDD>-<영문-이름>`를 만듭니다.
2. `rules\ads-meta.md` §3대로 `ad.json`을 씁니다. 이 단계에서는 `name`과 `form`만 있으면 됩니다. 요청 문장의 질문·문구는 고치거나 다듬지 않고 글자 그대로 옮깁니다. 문장에 질문이 없으면 `form`을 빼서 표준 양식을 씁니다.
3. `node ads.mjs form <광고폴더> --check`를 실행합니다. ❌는 `ad.json`을 고쳐 다시 실행합니다. ⚠에 "개인정보처리방침 주소"가 있을 때만 §1의 "개인정보처리방침 주소" 요청 문장을 보냅니다.
4. 이어서 `node ads.mjs form <광고폴더>`를 실행합니다. 결과 코드 0이면 출력된 대조표(✅ 7줄)를 그대로 보고합니다. 양식은 만든 뒤 고칠 수 없으므로, 사람이 나중에 문구를 바꾸자고 하면 새 이름으로 새 양식을 만듭니다.

### 8.2 광고 만들기 (꺼진 상태)

1. 광고 이미지를 준비합니다. 블로그 글이 있으면 `cd C:\bas_mkt\tools\blog` 후 `node cards.mjs <글폴더> --ad <광고폴더>`로 `ad.png`(1080×1350)를 만듭니다. 사람이 준 이미지는 광고폴더에 복사합니다.
2. `rules\ads-meta.md` §4대로 `message`·`headline`을 쓰고 `daily_budget`·`image`(지역 광고면 `region`)를 `ad.json`에 넣습니다.
3. `cd C:\bas_mkt\tools\meta` 후 `node ads.mjs create <광고폴더>`를 실행합니다. 이미지 업로드, 캠페인, 광고 세트, 크리에이티브, 광고를 모두 꺼진 상태로 만듭니다. 그다음 Meta에서 다시 읽어 표준과 대조한 `review.html`을 만듭니다.
4. 결과 코드 0이면 대조표를 보고하고 §1의 "광고 확인" 요청 문장을 보냅니다. 광고 관리자 주소는 `review.html`에 있습니다.
5. 사람이 "게재 시작"이라고 답하면 `node ads.mjs launch <광고폴더>`를 실행합니다. 다시 대조해서 모두 같을 때만 광고 → 광고 세트 → 캠페인을 켭니다. 결과 코드 0이면 §1의 "게재 확인" 요청 문장을 보냅니다.

### 8.3 끄기와 상태 확인

- 사람이 "광고 꺼 줘"라고 하면 `node ads.mjs pause <광고폴더>`로 캠페인을 끕니다.
- 사람이 "광고 상태 알려 줘"라고 하면 `node ads.mjs status <광고폴더>` 출력을 그대로 전합니다. "승인 거부"가 있으면 검토 의견을 전합니다. 그리고 문구를 고친 광고를 새 이름으로 만들지 묻습니다.
- 광고 결과(노출·클릭)는 광고 관리자에서 사람이 확인합니다. 접수는 폴라애드가 연결한 홈페이지 관리자 대시보드의 상담신청과 텔레그램으로 받습니다. Meta의 잠재 고객 센터에서도 볼 수 있습니다. `create`·`launch` 출력의 두 주소를 그대로 전합니다.

| 코드 | 뜻 | 다음 행동 |
| --- | --- | --- |
| 0 | 완료 | 출력과 대조표를 보고합니다. |
| 8 | 같은 이름의 캠페인·양식이 이미 있음 | 다시 만들지 않습니다. 기존 것을 쓸지, 새 이름으로 만들지 사람에게 묻습니다. |
| 10 | `ad.json` 오류 | 출력대로 고친 뒤 다시 실행합니다. |
| 11 | API 오류 | 출력 마지막 줄과 `.private\logs\meta-ads.log` 마지막 10줄을 보고합니다. 같은 오류로 두 번 넘게 다시 실행하지 않습니다. |
| 13 | 다른 광고 작업이 실행 중 | 몇 분 뒤 한 번만 다시 실행합니다. |
| 17, 18, 19 | 결제 수단 없음 · 잠재 고객 약관 미반영 · 차별 금지 정책 미반영 | 17은 §1의 "결제 수단", 18·19는 "정책 동의 문의" 요청 문장을 보냅니다. 답을 받으면 같은 명령을 다시 실행합니다. 만든 것은 건너뛰고 이어서 합니다. |
| 20 | 다시 읽은 값이 표준과 다름 | **켜지 않습니다.** ❌ 줄을 그대로 보고하고 폴라애드에 문의하도록 안내합니다. |
| 21 | 앞 단계가 없음 | 출력에 적힌 명령(`form` 또는 `create`)부터 실행합니다. |

## 9. 보고 형식

- 점검·설치 결과는 표로 보고합니다(도구, 버전, 상태).
- 사람이 해야 할 일이 생기면 §1의 요청 문장 하나만 보내고 기다립니다.
- 네이버 세션 상태는 `check.mjs` 출력 한 줄을 그대로 전합니다. 쿠키 값은 적지 않습니다.
- 발행 결과는 글 제목, 예약 시각(바로 발행했으면 글 주소), 결과 코드를 한 줄로 보고합니다.
- 광고 결과는 광고 이름, 상태(꺼짐·검토 중·게재 중), 하루 예산, 결과 코드를 한 줄로 보고합니다.
