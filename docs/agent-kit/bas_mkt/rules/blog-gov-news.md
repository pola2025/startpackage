# 정부지원사업 소식 블로그 글 규칙

기업마당(bizinfo.go.kr) 공고를 바탕으로, 우리 회사(`brand.json`의 `company`)가 고객에게 정부정책자금·정부지원사업·소상공인 지원·창업 지원 소식을 전하는 네이버 블로그 글을 쓰는 규칙입니다. 작업 순서는 `AGENTS.md` §6을 따릅니다.

---

## 1. 리라이팅 원칙

이 글은 공고를 **우리 회사가 전하는 말투로 다시 쓰는 글**입니다. 다시 쓰는 목적은 원문과 문장 표현이 겹치지 않게 하는 것입니다. 내용을 바꾸는 것이 아닙니다.

1. **사실은 그대로 둡니다.** 금액·비율·기간·날짜·한도·대상·제외 조건·제출 서류는 `facts.json`과 `source\` 텍스트에 있는 값만 씁니다. 반올림하거나 합산한 숫자도 원문에 없으면 쓰지 않습니다.
2. **이름은 한 글자도 바꾸지 않습니다.** 사업명, 소관 부처·지자체, 수행 기관, 문의 부서, 협약 은행 이름은 공고 표기 그대로 씁니다. 사업명(`facts.json`의 `program`)은 본문에 원문 그대로 한 번 이상 씁니다. 줄여 부를 때는 원문 그대로 쓴 다음에만 줄입니다.
3. **표현은 바꿉니다.** 공고의 문장을 이어 붙이지 않습니다. 어순, 문장 길이, 어휘를 바꾸고, 공고의 개조식 항목은 읽는 사람에게 설명하는 문장으로 풀어 씁니다.
4. **없는 내용을 더하지 않습니다.** 공고에 없는 혜택, 선정 가능성, 심사 요령을 지어내지 않습니다. "이런 기업에 유리합니다"처럼 판단을 붙일 때는 공고 조건에서 바로 나오는 내용만 씁니다.
5. **단정·과장 표현을 쓰지 않습니다.** "선정 보장", "무조건", "100% 승인", "누구나 받을 수 있는", "최대 혜택" 같은 표현은 금지입니다. 우리 회사는 신청을 돕는 곳이지 선정을 결정하는 곳이 아닙니다.
6. **공고 밖 자료는 출처가 있어야 합니다.** 2025년의 흐름, 2026년에 달라진 점, 앞으로의 전망은 `sources.json`에 적은 기사·발표 내용만 씁니다. "○○부는 ~라고 밝혔습니다", "○○ 보도에 따르면"처럼 누구의 말인지 드러나게 씁니다. 에이전트가 스스로 전망을 만들지 않습니다.

## 2. 글 구조

`build.mjs`가 아래 표의 차례대로 조립합니다. 모든 이미지 사이에는 문단이 들어갑니다.

| 순서 | 블록 | 내용 |
| --- | --- | --- |
| 1 | 표지 이미지 | 대형 타이포 + 주제에 맞는 실사 배경(`photos\cover.png`) |
| 2 | 리드 문단 | 어떤 공고인지, 누가 관심을 가져야 하는지 |
| 3~10 | 메시지 카드 4장 + 카드마다 뒤 문단 | 공고의 핵심 네 가지(규모·방식·조건·기간 등) |
| 11~ | 소제목 7개 + 섹션 본문 | 섹션마다 문단과 차트·실사를 번갈아 배치 |
| 끝 | 정리 문단 → 출처 → CTA 이미지 → 태그 | CTA는 홈페이지 링크가 걸린 고정 디자인 |

앞 다섯 장(표지 + 카드 4장)은 네이버 피드 미리보기에 그대로 걸리는 이미지입니다. 글을 열지 않은 사람도 이 다섯 장만 보고 무슨 공고인지 알 수 있어야 합니다.

### 섹션 7개 기본 구성

공고에 맞게 바꿔도 됩니다. 단, 7개를 유지하고 각 섹션은 서로 다른 내용을 다룹니다.

1. 지원 대상 (누가 신청할 수 있는지)
2. 제외 대상·제한 조건
3. 지원 규모·한도
4. 지원 내용·조건 (금리, 비율, 기간)
5. 신청 방법·제출 서류
6. 선정 뒤 의무·유의사항
7. 정책 흐름과 전망 (2025년 → 2026년 → 앞으로, 출처 자료 기반)

## 3. 문구 기준

### 표지 (`cover`)

- `lines` 1~2줄 + `accent` 1~2줄, 합쳐서 4줄 이하입니다. 한 줄은 8자 이내입니다.
- `lines`에는 누구의 무슨 사업인지(지역·대상·사업 종류), `accent`에는 가장 중요한 숫자나 혜택을 씁니다.
- `sub`는 공고 이름을 줄인 한 줄입니다. 피드 미리보기에서는 읽히지 않으므로 핵심을 `lines`·`accent`에 둡니다.

### 메시지 카드 (`cards`)

- 4장입니다. 각 카드는 `label`(4~6자)과 `lines` 2줄입니다. 한 줄은 7자 이내입니다(영문·숫자·공백은 반 글자로 셉니다).
- 네 카드는 서로 다른 층위를 말합니다. 예: 규모 → 방식 → 조건 → 기간.
- 카드 문구는 근거 섹션(`section`)의 본문 표현과 맞춥니다. 어느 글에나 붙는 범용 문구를 쓰지 않습니다.
- `text`는 그 카드를 풀어 주는 문단입니다. 카드와 같은 숫자를 문장으로 설명합니다.

### 소제목 (`sections[].heading`)

- 진단 질문형("누가 신청할 수 있나요?") 또는 점검형("신청 절차와 제출 서류 체크")으로, 끝맺은 문장이나 구로 씁니다.
- "~하는지", "~인지"로 끝나는 흐릿한 조각은 쓰지 않습니다.
- 14자 이내로 씁니다. 이미지 가운데 칸에서 두 줄로 자동 줄바꿈됩니다.

### 본문 문단

- 우리 회사가 고객에게 전하는 존댓말("~합니다")로 씁니다. 회사 이름은 리드와 정리에서 한 번씩만 씁니다.
- **한 줄은 한글 20자 이하**입니다. 의미 단위로 줄을 바꿉니다. 단어 중간에서 끊지 않고, 줄 끝에 한두 글자만 남기지 않습니다.
- **문단은 맥락 단위**입니다. 한 문단은 같은 이야기를 하는 2~4줄입니다. 한 줄마다 문단을 나누지 않고, 다섯 줄 이상 이어 쓰지 않습니다.
- 문단 사이에는 빈 줄 하나를 둡니다(`\n\n`). 한 블록 안에 문단을 여러 개 넣어도 됩니다.
- 첫 문장은 그 공고에만 해당하는 내용으로 시작합니다. 다른 글과 같은 첫 문장, "요즘", "많은 분들이" 같은 흔한 도입은 쓰지 않습니다.
- 본문에 주소(URL)를 쓰지 않습니다. 링크는 CTA 이미지에만 걸립니다.

### 분량

- 본문(리드 + 카드 문단 + 섹션 문단 + 정리)이 **공백 포함 2,800자 이상**이어야 합니다. 출처와 태그는 세지 않습니다.
- 공고만으로 부족하면 7번 섹션을 출처 자료로 채웁니다. 같은 말을 되풀이해서 분량을 늘리지 않습니다.

### 정리·출처·태그

- `closing`은 공고의 핵심과 신청 전에 챙길 일을 2~3문단으로 정리합니다.
- `sources`는 공고 이름·기관·등록일, 인용한 기사의 매체명·날짜를 적습니다. 주소는 적지 않습니다. `build.mjs`가 "출처" 문단으로 정리 문단 아래에 넣습니다.
- `tags`는 5~10개입니다. 지역, 사업명 핵심어, 자금 종류, 대상을 넣습니다.

## 4. 차트

공고에 기간·금액·비율·한도가 있으면 2~4개를 넣습니다. 숫자는 모두 공고나 출처 자료에 있는 값이어야 합니다. 차트 하단에는 `facts.json`의 `sourceLabel`이 출처로 자동으로 들어갑니다.

| 종류 | 언제 | 데이터 |
| --- | --- | --- |
| `bar` | 금액·규모 비교 | `"items": [["경영안정자금", 2100], ["시설자금", 300]]` (숫자) |
| `table` | 한도·대상·서류처럼 짝이 있는 정보 | `"rows": [["5억 원", "특례대상 기업"], ["3억 원", "공장등록 제조업체"]]` (2~5행) |
| `timeline` | 기간·단계·일정 | `"steps": [{ "label": "거치기간 2년", "value": "연 2.5%", "weight": 2 }, …]`, 선택 `"note"` |
| `stats` | 기한·의무·핵심 수치 2~4개 | `"items": [{ "value": "6개월", "suffix": "안에", "text": "총 융자금의 70% 이상 사용" }, …]`, 선택 `"warn": 2`(빨간색으로 강조할 항목 번호, 0부터) |

- 공통: `"title"`(18자 이내), `"unit"`(단위·조건을 적는 작은 글씨, 없으면 빈 문자열).
- 공고 밖 자료(`sources.json`)의 숫자로 만든 차트는 `"source"`에 매체명과 날짜를 적습니다(예: `"쿠키뉴스 2026년 2월 4일 보도"`). 비워 두면 공고 이름이 출처로 들어갑니다.
- `timeline`의 `weight`는 막대 길이 비율입니다(기간이 2년·1년이면 2·1).

## 5. 실사 이미지

- 4~5장을 섹션 사이에 나눠 넣습니다. 한 섹션에 두 장을 몰지 않고, 이미지끼리 붙이지 않습니다.
- 그 공고의 업종과 절차에 맞는 한국 업무현장을 고릅니다. 예: 제조업 자금이면 공장·설비, 신청 절차면 은행 창구·서류, 창업이면 작은 사무실.
- 글자·숫자·로고·간판·워터마크가 없어야 합니다. 서류는 빈 종이나 읽을 수 없는 상태로 둡니다.
- 인물은 뒷모습·옆모습·어깨 너머로 담아 얼굴이 주인공이 되지 않게 합니다.
- 표지 배경(`cover.png`)은 가운데에 큰 글자가 올라가므로 가운데가 복잡하지 않은 넓은 장면으로 만듭니다.
- 생성 이미지에는 `build.mjs`가 오른쪽 아래에 "AI 생성 이미지"를 자동으로 표기합니다. 실제 고객사 현장 사진이라고 쓰지 않습니다.
