# D1/R2 운영 전환 전 위험·보안 점검

점검일: 2026-09-08 KST. 판정: **운영 전환 보류**.

기존 앱 코드, 준비된 D1 코드, 로컬 이관 스냅샷, 프로젝트 설정, 공식 보안 권고를 읽기 전용으로 점검했다. 이 보고서 외 앱 코드·운영 데이터·자격증명 변경, 고객 발송, 배포는 수행하지 않았다. 기존 취약점과 아직 완성되지 않은 마이그레이션을 구분한다. 침해 발생 여부를 판정하는 포렌식 보고서는 아니다.

Next.js AVIF 이미지 최적화 관련 권고는 2026-08-25 공개됐으며 15.5.24에 수정됐다. 실제 공격 성공을 재현하지 않았다. [공식 Next.js 권고](https://github.com/vercel/next.js/security/advisories/GHSA-2xp9-vwfh-vxw4)

Windows 호스팅 서버에 한정되는 별도 RCE 권고도 같은 패치 기준이다. 로컬 개발 PC가 Windows라는 이유로 운영 서버에 이 조건이 해당한다고 판단하지 않는다. [공식 Windows 호스팅 권고](https://github.com/vercel/next.js/security/advisories/GHSA-p293-qw3h-jr36)

설치된 `next-auth 5.0.0-beta.30`도 설정 오류와 세션 객체 존재 검사 조합에 관한 권고 범위에 포함된다. 권고 표의 수정 버전은 beta.32이다. 개별 API에서 사용자 ID·역할 검사까지 확인해야 하며, 현재 인증 우회가 재현됐다는 뜻은 아니다. Credentials Provider 사용으로 이메일/OAuth 전용 권고의 직접 적용 범위는 낮다. [공식 Auth.js 권고](https://github.com/nextauthjs/next-auth/security/advisories/GHSA-8fpg-xm3f-6cx3)

패키지 설치·업데이트나 registry 감사는 실행하지 않았다. 환경의 패키지 매니저 금지 규칙에 따라 버전 확인과 공식 권고 대조만 수행했다.

## 2. 파일 접근과 비용 위험

- **조건부 높음 — 비공개 파일의 공개 URL 경로:** `lib/storage/r2Client.ts:26` 업로드 결과를 `R2_PUBLIC_URL`로 반환한다. 일반 첨부·관리자 시안 업로드에서 이 경로를 사용한다. 실제 버킷/도메인의 익명 접근 정책은 확인하지 않았으므로 공개 유출로 단정하지 않는다. 공개 자산과 고객 자료를 분리하고, 비공개 자료는 소유권 확인 후 짧은 서명 URL로 제공해야 한다. 기존 컨펌 링크 호환성을 함께 검증해야 한다.
- **높음 — 직접 업로드의 실제 크기 제한 공백:** `app/api/upload/presign/route.ts:52`는 클라이언트가 보낸 size만 검사한다. `lib/storage/r2Client.ts:75` 서명 생성에 길이 제한이 없다. `profile-finalize/route.ts:59`는 객체 전체를 메모리에 읽은 다음 68행에서 20MB를 검사한다. 사후 크기·매직바이트 검증은 존재하지만 저장/메모리 비용 발생을 선제 차단하지 못한다. 업로드 발급 제한, 실제 바이트 상한, 제한된 스트림 읽기, 미완료 임시 객체 수명 정책을 검증해야 한다. 운영에 큰 파일을 올리는 시험은 하지 않았다.
- **중간 — 다운로드 외부 요청 제한 부족:** `app/api/workflows/download/route.ts:70` 저장된 URL을 제한 없이 fetch하고 79행에서 전체 버퍼를 만든다. 사용자 소유권과 DB의 시안 URL 일치 검사는 존재하므로 임의의 익명 SSRF로 분류하지 않는다. 잘못 저장된 URL에 대비한 호스트/프로토콜/리다이렉트 제한, 타임아웃, 바이트 상한이 필요하다. 다운로드 횟수 검사와 증가도 원자적으로 처리해야 한다.
- **중간 — 파일 검사 편차:** 일반 첨부·공지·관리자 시안 업로드의 MIME/실제 파일 내용 검증 수준이 다르다. 허용 유형과 크기 정책을 통일하고 파일 내용으로 판정해야 한다. 프로필 finalize에는 실제 파일 타입 검사가 있으므로 모든 경로가 MIME만 신뢰한다고 일반화하지 않는다.
- **중간 — 재발급 응답과 로그:** 재발급 응답은 등록 여부·SMS 동의 여부를 구분하고 성공 시 이름을 포함한다. SMS 전송 실패 전에 비밀번호가 바뀌는 순서도 확인했다. 일반화된 응답, 전송 실패 복구, 개인정보 로그 마스킹이 필요하다.

## 3. D1 전환 자체의 차단 항목

1. **앱 연결 미완료:** `.omx/d1-migration/cutover-gate.json`은 `runtimeReady=false`, 잔여 파일 106개, `productionCutoverAllowed=false`다. 이 수는 스캔 기준이며 모두 독립 API라는 뜻은 아니다. 실제 앱은 아직 Prisma/PostgreSQL을 사용한다. `callDataService`는 정의만 있고 앱 호출부가 없다.
2. **최종 변경분 동기화 없음:** 현재 D1은 시점 스냅샷이다. 원본에 이후 쓰기가 계속되면 D1과 달라진다. 최종 쓰기 중지/최종 이관·검증/읽기와 쓰기 동시 전환/재개 절차가 필요하다. 전환 후 D1에 새 쓰기가 생긴 뒤에는 단순히 예전 DB로 되돌리는 롤백도 데이터 유실을 만들 수 있으므로 역동기화 또는 복구 기준을 정해야 한다.
3. **API 계약과 전체 조회:** `app/api/communication/threads/route.ts:16`은 메시지를 포함한 전체 목록을 조회하고 배열로 반환한다. Worker는 `{items,nextCursor}`를 반환한다. 프론트 페이지네이션과 Date/JSON/boolean 변환까지 연결해야 한다. 새 Worker의 제한은 기존 API에 자동 적용되지 않는다.
4. **쓰기와 재시도 미연결:** 새 signup/confirm 명령은 원자적 batch와 충돌 검사가 있지만 기존 운영 라우트에 연결되지 않았다. 성공 후 응답 유실에 대한 멱등 키/상태 재조회 정책도 필요하다. 확정·수정·발주·배송지·인쇄 색상 고지와 동의 이력을 유지하는 통합 회귀 검증이 남았다.
5. **서비스 접근 설정 미완료:** Worker 설정은 staging DB를 가리키며 workers.dev/preview URL은 꺼져 있다. 프로젝트 환경에서 서비스 URL·토큰·커서 서명 키가 확인되지 않았다. 현재 실패 시 차단하는 방향이지만 운영 경로가 준비됐다는 뜻은 아니다. 서버 전용 접근과 최소 권한 토큰을 구성해야 한다. 공용 서비스 토큰 유출 시 다른 userId를 지정할 수 있는 신뢰 경계도 고려해야 한다.
6. **호출 제한과 비용 상한은 별개:** 새 Worker의 페이지 기본 20/최대 50, 서명 커서, 인덱스, 15초 캐시, 동시 실행·메모리 제한은 확인했다. 다만 인스턴스 캐시는 전역 캐시가 아니고, 캐시 적중에도 사용자/소유권 조회가 남는다. 쓰기 후 캐시 무효화, 누적 비용 관측과 차단 정책이 필요하다.

Cloudflare Rate Limiting binding은 지역별이며 정확한 전역 회계 카운터가 아니다. 현재 60회/60초 설정을 계정 전체 일일 비용 보장으로 해석하면 안 된다. [Cloudflare 공식 설명](https://developers.cloudflare.com/workers/runtime-apis/bindings/rate-limit/)

## 4. 검증 결과와 한계

- 이번 점검에서 D1 관련 **4개 테스트 파일, 27개 테스트 통과**. 키셋 조회 및 최신 시안 조회의 SQLite 실행 계획에서 해당 인덱스 사용을 확인했다.
- 기존 이관 기록: 24개 테이블, 5,324행 값·관계 검증. 원격 검증 143요청, 5,328 rows_read. 이번 점검에서 원격 전체 조회를 반복하지 않았다.
- `.env`, `.env.local`, `.env.production`, `.env.vercel`은 Git 제외 확인. 일부 알려진 비밀 패턴의 추적 파일 검색에서 실제 키로 확인된 항목은 없었으나 Git 이력 전체와 모든 비밀 유형을 검증한 것은 아니다.
- `.vercelignore`는 존재하지만 아직 untracked다. 마이그레이션과 기존 UI 변경이 함께 있는 작업 트리이므로 배포 전 포함 범위와 세 가지 계정 신원을 다시 확인해야 한다.
- 프로젝트에 Cloudflare Global API Key 설정이 있고 scoped API token은 확인되지 않았다. 운영 서비스에 광범위 키를 재사용하지 않도록 해야 한다. 키 값은 출력하지 않았다.
- 실제 R2 익명 접근, 운영 WAF, 배포된 의존성 버전, 분산 부하, 외부 발송을 포함한 운영 E2E, 침해 여부는 검증하지 않았다. 로컬 테스트 통과는 운영 전환 허가가 아니다.

## 5. 권장 처리 순서와 완료 조건

1. 평문 비밀번호 기록·인증 제한·관리자 권한 회수 문제를 보완하고 공식 보안 패치 적용 경로를 준비한다.
2. R2 접근 정책과 업로드/다운로드 자원 상한을 확인·보완한다.
3. 전체 API를 D1 경로에 연결하고 페이지네이션·응답 계약·쓰기 원자성·멱등성·캐시 무효화를 검증한다.
4. 기존 컨펌/발주 내용과 동의 기록이 보존되는 스테이징 통합 테스트를 수행한다. 고객 발송은 격리한다.
5. 최종 동기화와 전환 후 쓰기까지 고려한 복구 리허설을 마친 뒤 버전 기록·배포 신원을 검증하고 운영 전환한다.

현재 점검의 완료 조건은 위험과 미검증 범위를 근거와 함께 정리하는 것이다. 보안 수정과 운영 전환은 아직 완료하지 않았다.
