# 사용자·관리자 D1/R2 전환 전 실점검

점검일: 2026-09-08 KST. 판정: 운영 전환 보류.

## 환경과 데이터 경계

- 요청 계정의 운영 데이터는 읽기 전용으로 17개 모델을 백업했다. 운영 계정 초기화·데이터 변경은 하지 않았다.
- 로컬 계정 사본의 접수 내역을 초기화하고 Chrome에서 사용자와 관리자 계정을 각각 로그인했다.
- 최신 Next production build와 실제 D1 Worker 코드를 로컬 SQLite 어댑터로 실행했다. PostgreSQL 연결은 사용할 수 없는 로컬 주소로 설정했다.
- 파일은 로컬 S3/R2 전송 모사 환경을 사용했다. 실제 Cloudflare 배포·R2 서명 검증을 이번 브라우저 결과로 보장하지 않는다.
- 외부 알림 제공자 자격증명은 제거했다. 카드 이미지 업로드 응답만 브라우저에서 모사했고, Gmail·카드 입력은 가상 값으로 검증했다. 고객 메시지 발송과 실물 발주는 하지 않았다.
- 현재 배송 정책을 확인하도록 로컬 사본의 기수 날짜를 조정했다. 기존 기수의 날짜 정책은 별도 회귀 검증 대상이다.

## 발견하여 수정한 기능 문제

- D1 최초 제출 레코드 생성 시 입력 손실 및 동시 생성 충돌.
- 연속 업로드 단계에서 같은 파일을 선택할 때 저장이 누락되는 문제와 업로드 성공 후 저장 재시도 처리.
- 자동 생성된 워크플로우를 이미 접수한 것으로 판정하여 최초 제작 요청 버튼이 사라지는 문제.
- 관리자 워크플로우의 중첩 사용자 데이터 누락 및 저장 후 목록 갱신 누락.
- 로고 확정 UI가 서버에서 요구하는 동의 정보를 전달하지 않는 문제.
- 관리자 발주 완료에서 예상 도착일 문자열을 날짜로 검증하여 저장이 실패하는 문제.
- 대용량 요청에서 multipart 본문 파싱 실패가 일반 오류로 반환되는 문제.
- 직접 인쇄 발주가 기본 동의와 배송지 확정 기록을 생략하던 문제. 공용 확정 창·검증·배송지 스냅샷 저장으로 보완했다.
- D1 제출 조회에서 배송지 필수 정책 flag가 누락되어 확정 창의 배송 단계가 표시되지 않던 문제.

## 운영 적용 차단 항목

1. **기존 데이터 전환:** 새 저장의 AES-256-GCM 암호화, 기본 응답 마스킹, super 관리자 명시적 열람, 로그 제거를 적용했다. Slack 업무 전달은 사용자 지시에 따라 유지한다. 로컬 실제 재저장·새로고침·암호문 저장·열람 후 닫기·사용자 열람 거부를 검증했다. 운영 기존 데이터는 최종 쓰기 중단 후 별도 암호화 스냅샷으로 이전해야 한다.
2. **D1 시안 목록:** 관리자·사용자 목록과 상세를 D1으로 전환했다. 관리자 목록 2→3개 추가 조회와 106개 메시지, 사용자 상세 20→40→60→80→100→106개 조회를 실검증했다. 중첩 응답 누락과 사용자 미확인 개수도 수정했다. 8개 필터 조합의 인덱스와 페이지 후보 선조회로 전체 후보 스캔을 제거했다. 최종 사용자·관리자 목록 더보기, 106개 메시지 전체 조회, 사용자 읽음 처리, 관리자 유형·상태·사용자 필터의 200 응답을 확인했다.
3. **D1 운영 준비:** Worker 배포·Secret 설정, 추가 원격 마이그레이션, 쓰기 중단 후 최신 데이터 재동기화·대조가 남아 있다. 로컬 기능 통과와 운영 전환 완료는 별도로 판정한다.

확정 이후 배송 필드 변경 제한은 보완했다. 실제 자동 저장 요청에서 변경은 409, 동일 값은 200이며 저장된 주소가 유지됨을 확인했다. 기존 발주의 확정 스냅샷을 새로 만들어 과거 동의를 추정하지 않는다.

23:10 KST 암호화 리허설: 운영 데이터를 읽기 전용 반복 읽기 트랜잭션과 ID 커서로 71회 조회하여 24개 테이블 5,329개 행을 별도 백업했다. 민감정보를 포함한 제출 50개 행을 암호화하고 복호화 동등성, 전체 값 동등성, 외래키 검증을 통과했다. 원본 백업은 변경하지 않았으며 운영 DB에도 쓰지 않았다. 이 리허설은 쓰기 동결 후 최종 스냅샷을 대신하지 않는다.
