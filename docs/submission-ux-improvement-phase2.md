## 1. 사용자 여정 맵

### 1.1 타겟 페르소나

| 항목 | 내용 |
|------|------|
| **이름** | 김대표 (가상) |
| **연령** | 45세 |
| **직업** | 소규모 사업장 대표 |
| **IT 친숙도** | 낮음 (스마트폰 기본 사용 가능) |
| **상황** | 비즈액터스쿨 교육 수료 직후, 자료제출 필요 |
| **목표** | 빠르게 자료를 제출하고 홈페이지/명함 제작 진행 |
| **불안** | "뭘 준비해야 하지?", "어디까지 해야 끝나지?" |

### 1.3 단계별 Pain Point 상세

| 단계 | Pain Point | 원인 | 이탈 위험도 |
|------|------------|------|------------|
| **1. 진입** | 없음 | - | ⭐ (낮음) |
| **2. 탐색** | "이게 다 뭐지?" | 6개 탭이 한눈에 보임, 40+ 필드 압도 | ⭐⭐⭐⭐ (높음) |
| **3. 입력** | "필수가 뭐지?" | 필수/선택 구분 불명확, 진행률 표시 약함 | ⭐⭐⭐ (중간) |
| **4. 업로드** | "파일이 안 올라가네" | 크기/형식 제한 미인지, 대안 부재 (→ Phase 1 해결) | ⭐⭐⭐ (중간) |
| **5. 탭 전환** | "다음이 뭐지?" | 순서 가이드 없음, 자유탭 구조의 단점 | ⭐⭐⭐⭐ (높음) |
| **6. 완료** | "제출 완료된 거 맞나?" | 최종 확인 화면 없음, 피드백 부족 | ⭐⭐⭐ (중간) |

### 1.4 이탈 원인 가설

1. **인지 과부하 (Cognitive Overload)**
   - 6개 탭 × 평균 7개 필드 = 42개 입력 요소
   - 사용자는 3-5개 이상의 선택지를 보면 결정 피로 발생

2. **진행감 부재 (Lack of Progress Feeling)**
   - 진행률 바가 있으나 탭별 상세 없음
   - "얼마나 남았는지" 체감 어려움

3. **순서 혼란 (Sequence Confusion)**
   - 탭 자유 이동 가능하나 권장 순서 없음
   - "어디서 시작해야 하는지" 모름

4. **맥락 단절 (Context Break)**
   - 왜 이 정보가 필요한지 설명 부족
   - 민감정보(계정) 입력 시 불안감

## 2. 개선안 상세 설계 (PRD)

### 2.1 개선 전략 개요

| 전략 | 설명 | 기대 효과 |
|------|------|----------|
| **A. 온보딩 화면** | 시작 전 준비물/예상시간 안내 | 압도감 해소, 준비도 향상 |
| **B. 진행률 시각화** | 섹션별 체크리스트 + 힌트 | 진행감 체감, 이탈 방지 |
| **C. 단계별 가이드** | 순차 진행 권장 (선택적) | 순서 혼란 해소 |
| **D. 비주얼 선택** | 카드형 선택 UI (로고/명함) | 입력 부담 감소 |
| **E. 제출 전 요약** | 최종 확인 화면 | 완료 확신, 누락 방지 |
| **F. 신뢰도 UI** | 민감정보 보안 안내 | 불안감 해소 |
| **G. 에러 메시지** | 친절한 톤의 에러 안내 | 좌절감 감소 |
| **H. 모바일 특화** | 모바일 환경 최적화 | 이탈률 감소 |

#### 2.1.1 용어 순화 가이드

> **원칙**: 45세 IT 비친숙 사용자가 **혼자서**, **불안 없이** 이해할 수 있는 용어만 사용

| 현재 용어 | 순화 용어 | 적용 위치 |
|----------|----------|----------|
| 업로드 | "파일 올리기" 또는 "사진 첨부" | 모든 파일 필드 |
| PDF | "(사진 또는 문서 파일)" | 파일 형식 안내 |
| "1000px 이하" | 삭제 또는 "용량 10MB 이하" | 이미지 안내 |
| Wizard 모드 | "단계별 안내" | 모드 선택 |
| Tab / 탭 | "메뉴" 또는 "항목" | 네비게이션 |
| Step | "단계" | 진행 표시 |
| 컬러 컨셉 | "원하는 색상" | 디자인 필드 |
| 타이포그래피 | "글꼴 스타일" | 디자인 필드 |
| 미니멀 / 트렌디 | "깔끔한" / "요즘 스타일" | 스타일 선택 |
| 드래그 앤 드롭 | "끌어다 놓기" 또는 생략 | 파일 업로드 |
| 썸네일 | "미리보기 이미지" | 파일 표시 |
| 진행률 | "완료 현황" | 상단 바 |

**적용 규칙**:
- UI에 표시되는 모든 텍스트는 순화 용어 사용
- 코드/내부 문서에서만 기술 용어 사용
- 영어 단어는 한글로 대체

#### 힌트 메시지 로직

```typescript
interface NextActionHint {
  section: string;
  field: string;
  message: string;
}

function getNextActionHint(progress: ProgressResult): NextActionHint | null {
  // 미완료 섹션 중 첫 번째 찾기
  const incomplete = progress.sections.find(s => !s.isComplete);
  if (!incomplete) return null;

  // 섹션별 힌트 메시지 매핑
  const hints: Record<string, string> = {
    '브랜드정보': '브랜드명을 입력해주세요',
    '사업자등록증': '사업자등록증을 업로드해주세요',
    '프로필사진': '대표자 프로필 사진을 업로드해주세요',
    '명함스타일': '명함 색상을 선택해주세요',
    '로고': '로고 선호 스타일을 선택해주세요',
    '홈페이지': '홈페이지 컬러 컨셉을 입력해주세요',
    '마케팅': '인스타그램 계정 정보를 입력해주세요',
  };

  return {
    section: incomplete.name,
    field: incomplete.fields[0],
    message: hints[incomplete.name] || '다음 항목을 입력해주세요',
  };
}
```

| 완료된 섹션 체크 | hover 시 "클릭하면 수정할 수 있어요" 툴팁 |

### 2.4 C. 단계별 마법사 vs 탭 구조 분석

#### 비교 분석

| 항목 | 탭 구조 (현재) | 단계별 마법사 |
|------|---------------|--------------|
| **장점** | 자유 탐색, 빠른 수정 | 순서 명확, 집중도 높음 |
| **단점** | 압도감, 순서 혼란 | 유연성 부족, 되돌아가기 불편 |
| **적합 사용자** | 리터러시 높음, 재방문 | 리터러시 낮음, 첫 방문 |

#### 권장: 하이브리드 방식

```
┌─────────────────────────────────────────────────────────────────┐
│                                                                 │
│  첫 방문자: 단계별 가이드 (Wizard) 모드                         │
│  ├── Step 1: 기본 정보 → Step 2: 서류 → ... → 완료              │
│  └── "탭 모드로 전환" 버튼 제공                                 │
│                                                                 │
│  재방문자: 탭 모드 (현재 방식)                                  │
│  ├── 자유롭게 탭 이동                                           │
│  └── 진행률 바로 현황 파악                                      │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

#### Wizard 모드 단계 구성

| Step | 이름 | 필드 수 | 예상 시간 |
|------|------|--------|----------|
| 1 | 기본 정보 | 5개 | 2분 |
| 2 | 필수 서류 | 2개 (업로드) | 2분 |
| 3 | 명함 스타일 | 2개 (선택) | 1분 |
| 4 | 로고 스타일 | 4개 (선택+입력) | 2분 |
| 5 | 홈페이지 | 2개 | 1분 |
| 6 | 마케팅 계정 | 4개 | 2분 |
| 7 | 최종 확인 | 요약 화면 | 1분 |

#### 가설 2: Wizard 모드 효과
```
H2: Wizard 모드 사용자는 탭 모드보다 소요시간이 20% 짧고 이탈률이 낮을 것이다.
```

| 항목 | 내용 |
|------|------|
| **독립 변수** | UI 모드 (Wizard vs Tab) |
| **종속 변수** | 소요시간, 이탈률, 완료율 |
| **Control** | 기존 탭 모드 |
| **Treatment** | 단계별 Wizard 모드 |

#### 가설 3: 진행률 힌트 효과
```
H3: "다음 행동" 힌트를 표시하면 다음 입력까지 소요시간이 30% 단축될 것이다.
```

| 항목 | 내용 |
|------|------|
| **독립 변수** | 힌트 표시 여부 |
| **종속 변수** | 다음 필드 입력까지 시간 |
| **Control** | 진행률 % 만 표시 |
| **Treatment** | 진행률 + "다음: OOO" 힌트 표시 |

```typescript
// lib/ab-test.ts

type TestGroup = 'control' | 'treatment';

interface ABTestConfig {
  testId: string;
  allocation: number; // 0-1, treatment 비율
}

export function assignTestGroup(
  userId: string,
  config: ABTestConfig
): TestGroup {
  // 결정적 해시 (같은 유저는 항상 같은 그룹)
  const hash = hashCode(`${config.testId}-${userId}`);
  const normalized = (hash % 100) / 100;

  return normalized < config.allocation ? 'treatment' : 'control';
}

// 테스트별 설정
export const AB_TESTS = {
  ONBOARDING: { testId: 'onboarding-v1', allocation: 0.5 },
  WIZARD_MODE: { testId: 'wizard-v1', allocation: 0.5 },
  PROGRESS_HINT: { testId: 'hint-v1', allocation: 0.5 },
};
```

### D. 접근성 요구사항 (Accessibility Requirements)

> ⚠️ **중요**: UX 점검 결과 접근성 항목이 3/10점으로 가장 취약. 아래 요구사항 필수 구현.

#### D-1. 필수 요구사항 (WCAG 2.1 AA)

| 항목 | 요구사항 | 구현 방법 | 검증 |
|------|---------|----------|------|
| **라벨 연결** | 모든 input에 label 연결 | `htmlFor` + `id` 매칭 | axe DevTools |
| **터치 타겟** | 최소 44×44px | 버튼/링크 min-height: 44px | 수동 측정 |
| **색상 대비** | 4.5:1 이상 (본문) | 디자인 토큰 준수 | Lighthouse |
| **에러 연결** | 에러 메시지 연결 | `aria-describedby` | 스크린 리더 |
| **포커스 표시** | 키보드 포커스 시각화 | `focus-visible` 스타일 | 키보드 테스트 |

#### D-2. 키보드 네비게이션

```
Tab       → 다음 필드로 이동
Shift+Tab → 이전 필드로 이동
Enter     → 버튼 클릭 / 폼 제출
Esc       → 모달 닫기 / 취소
Space     → 체크박스 토글 / 카드 선택
Arrow     → 라디오/선택 옵션 이동
```

#### D-3. 스크린 리더 지원

| 요소 | aria 속성 | 예시 |
|------|----------|------|
| 필수 필드 | `aria-required="true"` | `<input aria-required="true">` |
| 에러 상태 | `aria-invalid="true"` | `<input aria-invalid="true">` |
| 에러 메시지 | `aria-describedby` | `<span id="error-name">` |
| 진행률 | `aria-valuenow` | `<div role="progressbar" aria-valuenow="67">` |
| 로딩 상태 | `aria-busy="true"` | `<button aria-busy="true">` |

| **Secondary** | 보조 액션 (이전, 취소) | 흰색 배경, 회색 테두리 |
| **Ghost** | 최소 강조 (스킵, 닫기) | 투명 배경, 파랑 텍스트 |
| **Destructive** | 위험 액션 (삭제) | 빨강 배경, 흰색 텍스트 |

#### E-3. 입력 필드 스타일

```
┌─────────────────────────────────────────────────────┐
│  브랜드명 *                          (필수 표시)    │
│  ┌───────────────────────────────────────────────┐ │
│  │ 입력값...                                     │ │
│  └───────────────────────────────────────────────┘ │
│  💡 고객에게 보여질 브랜드 이름입니다 (도움말)      │
└─────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────┐
│  브랜드명 *                          (에러 상태)    │
│  ┌───────────────────────────────────────────────┐ │
│  │                                   (빨강 테두리)│ │
│  └───────────────────────────────────────────────┘ │
│  ❌ 브랜드명을 입력해주세요 (에러 메시지)           │
└─────────────────────────────────────────────────────┘
```

#### E-4. 필수/선택 표시 규칙

| 상황 | 표시 방법 |
|------|----------|
| 필수 필드 | 라벨 우측에 빨간 `*` 표시 |
| 선택 필드 | 라벨 우측에 `(선택)` 텍스트 |
| 필수가 대다수 | 선택 필드만 `(선택)` 표시 |
| 선택이 대다수 | 필수 필드만 `*` 표시 |

### O. Disabled 조건 & 버튼 상태

#### O-1. 버튼별 Disabled 조건

| 버튼 | Disabled 조건 | Disabled 시 동작 |
|------|--------------|-----------------|
| **시작하기** (온보딩) | 없음 (항상 활성화) | - |
| **다음** (Wizard) | 현재 Step 필수 필드 미입력 | 클릭 시 미입력 필드 하이라이트 |
| **이전** (Wizard) | Step 1일 때 | 버튼 숨김 (Disabled 아님) |
| **탭 모드로 전환** | 없음 (항상 활성화) | - |
| **제출 전 확인하기** | 없음 (항상 활성화) | - |
| **제출 완료하기** | 필수 섹션 미완료 | 클릭 시 미완료 섹션 안내 |
| **저장** | 변경사항 없을 때 | 비활성화 표시 |
| **파일 업로드** | 업로드 진행 중 | 비활성화 + 진행률 표시 |

#### O-2. Disabled 버튼 디자인 전략

| 전략 | 설명 | 적용 |
|------|------|------|
| **A. 완전 비활성화** | opacity 50%, 클릭 불가 | 저장 버튼 |
| **B. 활성화 + 에러 안내** | 클릭 가능, 클릭 시 안내 | 제출 완료하기 |
| **C. 숨김** | 버튼 자체를 숨김 | 이전 버튼 (Step 1) |

**권장**: 주요 CTA는 **B 전략** 사용 (사용자가 왜 진행 못 하는지 알 수 있음)

#### O-3. 더블클릭 방지

```tsx
// 제출 버튼 더블클릭 방지
const [isSubmitting, setIsSubmitting] = useState(false);

const handleSubmit = async () => {
  if (isSubmitting) return;
  setIsSubmitting(true);

  try {
    await submitData();
  } finally {
    setIsSubmitting(false);
  }
};

<Button disabled={isSubmitting}>
  {isSubmitting ? (
    <>
      <Loader2 className="w-4 h-4 mr-2 animate-spin" />
      제출 중...
    </>
  ) : (
    '제출 완료하기'
  )}
</Button>
```

```
[에러 필드 표시]
```

#### QA용 최종 체크리스트 (R-10)

개발/QA 완료 전 반드시 점검:

```
[ 용어 ]
□ 모든 IT 용어를 일상 언어로 바꿨나요?
□ 영어 단어를 한글로 바꿨나요?
□ 전문 용어에 설명을 추가했나요?

[ 안심 ]
□ 모든 필드에 "왜 필요한지" 설명이 있나요?
□ 선택 필드에 "없어도 돼요" 안내가 있나요?
□ 민감 정보에 "안전해요" 안내가 있나요?

[ 실수 방지 ]
□ 제출 버튼에 확인 모달이 있나요?
□ 파일 삭제에 확인 모달이 있나요?
□ 제출 후 수정 가능 여부를 안내했나요?

[ 에러 ]
□ 모든 에러 메시지가 해결책을 알려주나요?
□ 에러 메시지가 친절한 톤인가요?
□ 자동 재시도 로직이 있나요?

[ 시각적 ]
□ 어디를 눌러야 하는지 한눈에 보이나요?
□ 필수(*) 표시의 의미를 설명했나요?
□ 진행률이 구체적인 숫자로 표시되나요?

[ 확인 ]
□ 파일 업로드 후 미리보기가 가능한가요?
□ 저장 완료 피드백이 명확한가요?
□ 제출 완료 후 확인 메시지(카톡/이메일)가 발송되나요?

[ 모바일 ]
□ 카메라 촬영 옵션이 있나요?
□ 입력 타입에 맞는 키보드가 뜨나요?
□ 화면 복귀 시 이어서 작성 안내가 있나요?

[ 신뢰 ]
□ "공식 서비스" 표시가 있나요?
□ 보안 관련 안심 문구가 있나요?
□ 문의 채널이 눈에 보이나요?

[ 최종 ]
□ 45세 IT 비친숙 사용자가 혼자서 완료할 수 있나요?
□ 중간에 멈춰도 불안하지 않나요?
□ 어디서든 "도움" 받을 수 있는 경로가 있나요?
```
