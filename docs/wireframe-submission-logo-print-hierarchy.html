설계 스펙 — Claude + Codex 합의

Codex 협의 결과 요약

1. 3-Layer 접근법 평가

  • Codex 동의: 3-Layer 모델은 정확하며 즉시 스캔 가능성을 개선할 것
  • Layer 1 (입력): 페이지를 지배해야 함 — 강한 테두리, 흰 카드, 전체 불투명도
  • Layer 2 (안내): 시각적으로 종속적 — muted gray 밴드, 접힌 팁, 인라인 캡션
  • Layer 3 (경고): 절제하여 사용 — 현재 경고끼리 경쟁 중 → 진짜 blocker만
  • 규칙: 입력 그룹당 1 primary card + 1 muted guidance + error만 alert 스타일

2. 로고 탭 — Step 기반 그룹핑

  • Step 1: 로고 파일 업로드 (선택 사항 명시)
  • Step 2: 디자인 선호도 — 스타일+폰트+색상을 하나의 "Design Preferences" 섹션으로
  • Step 3: 명함 색상 코드 — Required badge로, 큰 orange 박스 제거
  • Step 4: 상세 요청 — textarea가 주인공, 가이드는 접힌 아코디언으로
  • 라벨 16px semibold / 가이드 12-13px regular muted — 크기 차로 계층 표현
  • 경고 색상 1개로 통일 (orange 2개 → warning 1개)

3. 인쇄물 탭 — Step 분리

  • Step 1: 필수 서류 업로드 — 완료 상태 인라인 피드백
  • Step 2: 명함 스타일 — 3열 그리드 (데스크톱), 2열 (모바일)
  • Step 3: 계약서 스타일 — 별도 섹션으로 분리 (현재 같은 Card에 묻힘)
  • 섹션 헤더에 넘버링 + 완료 상태 표시

4. 추가 UX 패턴

  • Progressive Disclosure: 예시/가이드를 아코디언 뒤로
  • Completion Feedback: 섹션별 체크 상태 (1/2 완료)
  • Inline Validation: 반복 배너 대신 필드 근처 검증
  • Required Summary: 탭 상단에 "필수 항목 3개 남음" 표시가 다중 경고 박스보다 효과적
  • 일관된 Field Anatomy: Label → helper → input → error (혼합 금지)

5. 모바일 고려사항

  • 도움말 기본 접힘 — 필수 한 줄 가이드만 표시
  • 4열/6카드 레이아웃 금지 → 1-2열 또는 가로 스크롤
  • 필수 Badge를 라벨 옆에 (별도 alert 박스 대신)
  • 저장 버튼 sticky bottom 고려
  • 반복 배너 축소 — 모바일에서 입력을 fold 아래로 밀어냄
